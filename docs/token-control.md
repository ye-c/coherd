# Token 消耗控制

> 目标：在不影响工作质量前提下，降低 coherd 集群的 token 消耗。

## 1. 契约内优化（零成本，立即生效）

严格走 §3 路径式交审：executor 交审消息**正文 ≤ 400 字**（不含 DoD 逐条勾选清单——每条一行 `✓/✗` 不展开），只附 **`交审 <任务名>` + DoD 逐条 ✓/✗ + 产物绝对路径 + `git diff` 范围 + 关键取舍一句**，不转发产物正文。超 400 字的内容必须落文件，消息只送路径指针。**合并 N 票时按票计：每票 ≤400 字，合并消息总上限 = 400 × N**（DoD 勾选清单同样不计入）；批量审汇总消息每票一行、按票计。

- coordinator 不中转产物给 reviewer（executor 直交，§2 已在契约内）。
- 关键在执行：executor 交审消息压到 400 字内，不带代码片段（实测历史 p90 = 2470 字，源于契约只写"不可瘦到只剩路径"而无上限，agent 取宽口径）。

## 2. 通信精简

- 结论结构化：`approve: <理由要点>` / `revise: <问题清单逐条>`。
- agent 间消息用要点式，避免叙述铺陈。
- executor 交审消息**正文 ≤ 400 字**（不含 DoD 逐条勾选清单；合并 N 票时总上限 = 400 × N，按票计），保 `交审 <任务名>` + DoD 逐条 ✓/✗ + 路径 + `git diff` 范围 + 关键取舍一句。
- 回复对称义务按任务闭环计（§2），不重发、不纯 ack；收到 approve 不回 ack（无新信息）。

## 2.5 批处理（砍唤醒次数，是本节最大头）

每条消息 = 一次 `herdr agent prompt` = 对端一次完整 agent turn（重载 system prompt + 契约）。实测 1124 条消息里正文只占 token 约 2%，唤醒占约 98% —— 因此**减条数远优先于减字数**。

- **一批票据 = 一条分派消息**（分项列出）。不做的代价：4 票分 4 条 = 4 次唤醒，executor 每次重载上下文（w5h 实测）。
- **reviewer 批量审**：一轮唤醒审完同批全部票据、一条消息汇总逐票结论。不做的代价：曾 4 秒内被唤醒 8 次审 4 票。
- **60 秒合并阈值**：同收件人 60 秒内需发 ≥2 条同类消息 → 合并为一条。不做的代价：137 组同秒成串发送。
- **合并 ≠ 攒批**：合并是发送前规划（一次写完再发），**不是 sleep 等窗口**。禁止为凑批延迟——单条即刻可发就立刻发。不做的代价：契约里等于新开一条轮询/等待后门，与 §0「等待 = 转 idle」打架。

## 3. 规模缩放（§6 加硬判据）

简单任务跳过 reviewer 全链路（coordinator → executor → 交付）的硬判据：

```text
≤2 文件改动 + 无安全/正确性敏感面
```

任一条件不满足 → 必走 executor → reviewer → coordinator 全链路。

## 4. 输入端控制（token 大头在此）

- 消息引用路径，不贴大文件正文。
- 交审附 `git diff` 范围，reviewer 只读变更行。
- 长任务串轮换 session，防上下文膨胀。

## 5. 优先级（投资分派质量优先）

```text
1（契约内优化）→ 2（通信精简）→ 3（规模缩放判据）→ 4（输入端控制）
```

> **核心原则**：revise 循环最贵——一次返工的 token 消耗 > 一切通信压缩的收益。投资分派质量（清晰 objective / 可测 DoD / 精确边界）优先于压缩单条消息。

## 不做：静态模型分层

静态按角色降配（coordinator=haiku / reviewer=sonnet / executor=opus）**不做**——模型分层属用户 CLI 层配置（自行设 `COHERD_*_CMD` 指向不同 wrapper），coherd 框架不接管、不动态切换。
